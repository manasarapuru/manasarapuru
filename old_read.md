### 👋 About Me

Modern biology moves faster than the tools built to support it, and that gap is about to widen again. As AI agents start executing parts of the analysis pipeline itself, planning, running, and interpreting steps a researcher used to do by hand, the real design question stops being _____________. It becomes:
what the relationship between a scientist and an increasingly autonomous system should look like at all: how a researcher stays able to verify, steer, and trust a process they are no longer clicking through step by step.

I work on that problem as one system, not three separate concerns. Functionality, scalability, and usability get designed together, alongside the technical work of pairing open source biology foundation models with the machine learning and software engineering needed to make them usable by an actual researcher, not just runnable in a notebook.

This field is still early. There is no well worn job title for it yet, and most of the people equipped to notice the problem are not also the people building agentic systems. I want to help define what intuitive, trustworthy tool development looks like in bioinformatics as that shift happens, not after it has already settled.

**Professional experience**

My background is in molecular diagnostics, neurodegenerative disease research, and microbiology, working directly with genomic and transcriptomic data and the bioinformatics workflows built around them. That experience is the foundation for everything here. Every project starts from a real constraint I have run into, not a hypothetical one.

**Skills**

Human Computer Interaction: heuristic evaluation, cognitive load and attention theory, information architecture, usability testing, interaction design.
Computational Biology and Bioinformatics: drug discovery, genomics and transcriptomics pipelines, phylogenetics, molecular assay design, open source biology foundation models.
AI/ML: PyTorch, scikit learn, Claude Code, prompt engineering, model fine tuning, evaluation design, agentic system design.
Software Engineering: Python, React, API design.

## 🎯 What to Expect Here

This space is where I share prototypes at the intersection of biology, AI, and software engineering. Each project explores a scientific workflow, the pain point in it today, and what changes when part of that workflow is handled by an agent rather than a person, at the level of the interaction pattern, not just the interface on top of it.

**Process**
1. **Observe** a pain point in a real scientific workflow, usually one I have hit directly.
2. **Understand** why it exists, both at the interface level and at the level of the underlying computing pattern.
3. **Prototype** a working solution, pairing open source biology foundation models and machine learning where they belong, with an interface designed around how a researcher actually thinks.
4. **Open a conversation** with the people who would actually use it, about whether it holds up.

## 🔍 Scientific Challenges I'm Working On

If one of these is a problem you care about too, each entry links to how I have actually approached it, not just how I think about it.

**1. Scientific Interfaces** 🎨
How do we redesign scientific tools so their real complexity stays available, without burying the researcher in it on arrival, and what changes about that question once part of the tool is an agent rather than a fixed set of buttons?
My philosophy: complexity should be deferred, not deleted. As tools become more autonomous, the interface's job shifts from exposing options to making a system's reasoning inspectable and its actions reversible.
Example: Designing for Attention, a working series of redesigns applying this to Galaxy and the UCSC Genome Browser, including real user testing. [link]

**2. Scientific Workflows** 🔬
How can we make multi step research workflows more efficient, intuitive, and collaborative, especially as agents begin executing steps a researcher used to run by hand?
My philosophy: a workflow tool should mirror how a researcher actually thinks through a problem. When an agent proposes or runs a step, the researcher should be able to see the plan, edit it, and trust it before it executes, not just review the output after the fact.

**3. Data Interpretation** 📊
How can we help researchers explore and interpret complex biological data faster and with more confidence?
My philosophy: good data tools answer "so what" as fast as they answer "what," without oversimplifying the underlying result.

**4. Laboratory Technology** 🧪
How can software improve the way experiments are planned, executed, and analyzed?
My philosophy: lab software should reduce the gap between what happened at the bench and what gets recorded, not add another manual translation step.

**5. Precision Medicine** 🧬
How can technology help transform biological insight into better clinical decision making?
My philosophy: clinical tools succeed or fail on trust. Every design choice should make the reasoning behind a result easier to see, not just the result itself, and that matters even more once a model, not just a person, produced the reasoning.

**6. Scientific Communication** 💬
How can complex scientific knowledge be made easier to learn and interact with?
My philosophy: interactive explanation beats static explanation almost every time, especially for concepts that are inherently spatial or process driven.
Example: an AI cognitive assistant concept for scientific poster sessions, grounded in cognitive load theory. [link]

**7. Scientific Knowledge Navigation** 📚
How can researchers keep up with an ever growing body of literature and data?
My philosophy: navigation tools should be built around a researcher's actual question, not around the taxonomy a database happens to use.

**8. Sustainable Scientific Computing** 🌱
How can AI and computational biology become more efficient, computationally and environmentally?
My philosophy: the best model or pipeline is the smallest one that still gets the job done well, which matters more, not less, as agentic systems make more calls to bigger models by default.
